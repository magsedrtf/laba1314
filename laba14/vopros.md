## 1. Исходный код библиотеки (mylib.asm)

```nasm
section .data
    ; Ключ для XOR-шифрования
    encryption_key db 0x5A

section .text
    global asm_encrypt          ; экспортируем функцию

; Функция: asm_encrypt(char* data, int length)
; RDI = указатель на строку
; RSI = длина строки
asm_encrypt:
    cmp rsi, 0                  ; если длина <= 0 — сразу выход
    jle .done

    xor rcx, rcx                ; rcx = 0 (счётчик)

.loop:
    ; PIC-адресация: берём ключ относительно RIP
    mov al, [rel encryption_key]

    ; XOR текущего байта строки с ключом
    xor byte [rdi + rcx], al

    inc rcx                     ; следующий символ
    cmp rcx, rsi
    jl .loop                    ; пока не прошли всю строку

.done:
    ret
```

---

## 2. Сборка библиотеки

```bash
nasm -f elf64 mylib.asm -o mylib.o
gcc -shared mylib.o -o libmylib.so
```

## 4. Ответы на контрольные вопросы

### Вопрос 1
**В коде mylib.asm мы использовали синтаксис `[rel encryption_key]`. Объясните, как именно регистр процессора RIP помогает сделать скомпилированный машинный код позиционно-независимым (PIC).**

Регистр RIP хранит адрес следующей выполняемой инструкции.  
Синтаксис `[rel encryption_key]` заставляет процессор вычислять адрес переменной **относительно текущего значения RIP** (RIP + смещение).

Смещение между инструкцией и переменной всегда одно и то же, независимо от того, по какому базовому адресу операционная система загрузила библиотеку.  
Поэтому код остаётся рабочим при любой случайной загрузке (ASLR) — это и есть позиционно-независимый код (PIC).

### Вопрос 2
**Опишите назначение системных утилит nm и objdump. К какой подсистеме исполняемого файла (каким таблицам заголовка ELF) они обращаются, чтобы вывести список функций?**

Утилиты `nm` и `objdump` читают **таблицу динамических символов** ELF-файла (секции `.dynsym` и `.dynstr`).  

В этих секциях хранятся имена и адреса экспортируемых функций и переменных.  
Именно из этой таблицы динамический загрузчик (`dlopen` / `dlsym`) и модуль `ctypes` находят адрес функции `asm_encrypt` при загрузке библиотеки.

### Вопрос 3
**Что произойдет на уровне операционной системы, если в коде main.py закомментировать вызов my_asm_lib.asm_encrypt, но при этом оставить загрузку ctypes.CDLL("./libmylib.so")? Будет ли бинарный код библиотеки физически находиться в оперативной памяти компьютера?**

Да, бинарный код библиотеки **будет находиться в оперативной памяти**.  

Вызов `ctypes.CDLL(...)` внутри использует системный вызов `dlopen`.  
ОС проецирует страницы файла `.so` в адресное пространство процесса.  
Даже если ни одна функция библиотеки не вызывается, её код и данные уже загружены в ОЗУ.  
Выгрузка произойдёт только при завершении процесса (или при явном вызове `dlclose`).
